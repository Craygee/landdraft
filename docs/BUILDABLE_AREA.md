# Buildable Area screening — implementation and assumptions

## Inventory and preservation

Inspected before implementation: root AGENTS.md; SpatialAnalysisPanel (Turf buffer, centroid, union, intersection, difference, hull and derived-result destination dialog); MapCanvas / MapRef / desktop and mobile shells; ArcGIS paged viewport adapter; public catalog; import worker and geometry budgets; GeoJSON/KML/SHP export and print composer; GisLayer / LayerSource and project store serialization.

KEEP: all existing Analysis operations and results, elevation profiles, layer registry and public catalog, map editing, parcel selection, providers, records, project save/cloud sync, import/export and printing. ENHANCE: Analysis adds a Buildable Area entry, MapRef/shells mount its lazy panel, MapCanvas suspends ordinary selection/edit clicks while this tool owns the map. No component, provider, layer or capability is removed/replaced/deprecated. Switching to elevation profile closes this tool.

JSTS 2.7.1 (already a transitive Turf dependency) and proj4 2.21.0 (already transitive through shapefile import) are explicitly declared direct dependencies. Their existing exact package records are retained in bun.lock; workspace declarations were added. pnpm installation passed its supply-chain checks. No database migration or new provider login is needed.

## Workflow

Analysis → Buildable Area. Draw a rectangle by tapping/clicking two opposite corners, or explicitly choose a loaded polygon/multipolygon. Selected map features are prioritized in a bounded 800-item selector. Existing parcels, imported boundaries and drawings are supported. Original geometry is cloned, never modified. Gross acreage appears immediately. A JSON geometry editor edits only the study snapshot; Draw rectangle replaces it. Cancel/undo drawing, reset, cancel calculation, rerun and fit controls are available.

General Development and Data Center profiles request explicit completeness categories; Data Center additionally requests fiber. Categories include wetland, hydrology/drainage, flood/floodway, protected land/conservation, slope, electrical centerlines/towers/easements/distribution/substations/switchyards/storage, wind/solar/lease/access/collection, generation/pipelines/easements/wells, roads/access/rail/buildings and user restrictions. No source is auto-classified as legally prohibited. New constraints default to conditional; users explicitly choose exclusion or reference.

An explicit property polygon enables clipping and property setbacks. Ownership is not inferred from a rectangle. Property clipping uses the true polygon intersection. Property setbacks use the selected property shell AND internal hole boundaries. A separate study margin follows the effective study boundary. Property setbacks are not imposed on arbitrary clipping edges. Both default to zero and are explicitly user screening assumptions. Boundary-rule acreage is included in the union and shown separately in breakdown; it may overlap other rules.

Rules can use project layers, the existing import pipeline, manually drawn polygons or selected public services. Point/line deductions require an explicit buffer or a supplied footprint. Polygon/easement buffers default to zero. Distances are feet/metres; property/study margins are metres. Users can set geometry basis, source/document/date, verification (explicitly user-attested), classification, enabled state, buffer and documented coverage polygon. Source feature attributes, IDs, commodity/status and flood-zone codes remain in the snapshots. A local rule can explicitly detach from future layer edits and use its retained snapshot.

## Real integrations

Reuses catalog services: NWI wetlands, NHD flowlines, USGS water bodies and water areas, FEMA 1%/0.2% flood zones and separate floodways, Texas transmission, archived substations, USGS wind and photovoltaic facility data, groundwater/public-water wells, RRC pipelines, EPA Superfund/hazardous-waste facility points, USGS local roads, TxDOT road centerlines/rail and Round Rock municipal fiber. County/commodity and other source filters on existing layers are preserved. Historical substations and municipal fiber retain their catalog scope/limitations. Solar facility polygons are not assumed to be fully occupied arrays or unrestricted project land. These are public map data, not utility capacity or development approvals. A buffer added to recorded geometry is still provisional unless its setback basis is explicitly verified by the user.

Recorded easements, legal ROW, conservation instruments, turbine/solar occupied footprints versus lease boundaries, switchyards/storage footprints, legal entrances, internal roads and other unconnected restrictions require user layers/imports/documents unless an appropriate project layer exists. Categories without selected sources say Not evaluated. No integration is fabricated.

Source queries use the original study bounds expanded in projected metres by each rule's buffer plus 2 metres, with densified inverse-projected envelope edges. Features outside the study can therefore contribute buffered constraints inside. ArcGIS count and paged GeoJSON queries are compared; incomplete/changing responses are Partial. An empty successful query means no mapped features returned in those bounds, not real-world absence. Network/source failures produce failed coverage and NULL intersecting acreage, never a false zero or silent omission. No administrative coverage boundary is invented.

## Geometry and numerical method

`buildableArea.ts` runs in a dedicated worker, separate from UI and source loading. proj4 chooses a local WGS84 UTM zone/hemisphere; all buffering, topology, distances and areas operate in metres, not longitude/latitude degrees. Areas use projected square metres / 4046.8564224 per acre. Projection distortion and source accuracy remain screening limitations, not surveyed accuracy. Longitude/latitude exports follow GeoJSON WGS84 conventions; no projected coordinates are mislabeled as GeoJSON.

Supported study: valid WGS84 Polygon/MultiPolygon, latitude 80°S–84°N, local radius at most 25 km (approximately 50 km overall), no dateline-wide study. Source coordinates more than 1,000 km from projection origin are rejected with a request for clipped data. Coordinates use a 0.001 m grid; no geometry simplification or area-changing repair. Invalid/self-intersecting input is rejected for explicit source repair; a failed constraint is reported rather than silently repaired/dropped. JSTS buffers use 16 quadrant segments and round joins/caps. Inward buffers may split or completely remove candidate land.

Effective study = drawn/selected boundary ∩ explicit property only when clipping enabled. Union enabled exclusions plus selected boundary deductions, intersect with study, then subtract. Union conditional shapes, intersect remaining land and remove already excluded areas. Candidate = remaining, or remaining − conditional when the toggle is enabled. Candidate-outside-conditional is always separately reported. Individual rows may overlap; their sum is not the exclusion total. Reconciliation tolerance is max(0.05 m², study area × 1e−7).

Holes and all multipolygon components are retained. Shared-edge regions union normally; point-touching polygons remain separate components. Components are ordered by descending area with location tie-breaks and labeled stably within that result. Small remnants/slivers stay in totals, even if hidden by the display filter. Non-zero values below display precision say <0.01 ac. Geometric connectivity does not establish practical corridor width or legal access.

Known coverage polygons allow uncovered study geometry to be shown with a separate purple dotted pattern. Otherwise panel text reports uncertain coverage without inventing geographic boundaries. Classification and coverage are independent. “Evaluated with available data” describes the selected dataset/query, not comprehensive geographic clearance. Each requested category remains listed even when no rule loaded.

## Persistence, display and export

Each saved analysis is an ordinary derived GisLayer. `source.cacheProvenance.buildableArea` stores schema version 1, stable analysis ID, original source reference, boundary/property snapshots, all rule snapshots, classifications/overrides/buffers/coverage, settings, projected CRS, algorithm version 1.0.0, results and timestamp. Existing project save/version/cloud mechanisms serialize it intact. No viewport-source cache stripping applies to derived layers. Reopening uses snapshots, without silently refreshing live data. The normal project Save action persists/syncs the project.

Open/rename/update/duplicate/delete are in the tool and existing layer patterns. Duplicates get new analysis/component IDs. Renaming doesn't invalidate geometry. Input changes and known local rule/identified boundary edits mark results stale; saving/exporting stale calculations is blocked pending rerun. Remote viewport eviction alone does not invalidate a boundary snapshot. Deleted/unavailable boundary sources don't erase the stored geometry. Rerun is explicit and refreshes live rule sources; source failure remains visible.

Temporary map overlays show blue boundary, green candidate, red diagonal exclusions, amber crosshatch conditionals, grey reference and purple dotted unknown coverage. They are kept above other fills, do not alter project geometry and clean up on close/style change. Clicking an overlap reveals all matching prepared rules; component map/list inspection and zoom are supported. Saved layers use existing attribute symbology/patterns, map legend, feature attributes and print composition. The temporary display's minimum-component filter does not alter exports/totals.

Geometry GeoJSON includes study, exclusions, conditional areas, candidate components and known unknown-coverage geometry, with source IDs, timestamp/version and note. Summary GeoJSON includes the study/location, metrics, rule table, source/coverage metadata, assumptions and unresolved categories. Both use the existing mobile-capable export/download path. Print saved map opens the existing composer using saved styled layers; no separate PDF system was introduced.

## Responsiveness and budgets

The panel collapses for drawing; mobile reserves navigation/safe-area space. Header controls are at least 44×44 px and cannot scroll away. Only the content body scrolls; fit padding reserves space above/beside the panel. Mobile uses the panel's zoom buttons while overlapping native bottom controls are temporarily hidden; native controls restore on close. Other map interactions are suspended only while this tool owns the map.

Budgets: 20,000 study coordinates; 100,000 analysis/source coordinates; 4,000 features per rule; 60 rules; buffers/margins ≤5,000 m; worker timeout 45 s; source request timeout 25 s; saved snapshot ≤12 MB. Excessive data produce explicit errors with smaller-area/filter guidance. Source loads are sequential and cancelable; worker termination and generation tokens discard stale responses after edits/cancellation/unmount/project changes. Snapshots and existing HTTP service caching avoid reliance on a source for historical display; there is no claim of a new offline/public-source cache.

## Validation and limits

Automated tests use known metre-coordinate shapes transformed through WGS84/UTM and numerical tolerances: rectangles, single/external/overlapping exclusions, outside-line buffer/retrieval bounds, holes, multipolygons, conditional policy, full exclusion, property clipping/no intersection, distinct property/study margins and holes, inward collapse/splits, unit conversions, invalid geometry, missing/failed/partial source responses, NULL versus zero, known/unknown coverage, small components, stale generation tokens, serialization/reopen/duplicate/rename/export and remote viewport eviction. Existing GIS/pipeline/tooltip tests and TypeScript/lint/build checks also run.

Manual local UI QA used the actual SpatialAnalysisPanel, BuildableAreaPanel, real MapLibre and worker, with synthetic geometry and a small test project-layer persistence adapter rather than authenticated production data. Verified existing-polygon and two-corner rectangle entry, rules and policy change, deductions, overlap inspection of both rules, saved reopen after reload, rename/update, real geometry and summary downloads (parsed the generated files), and desktop/tablet 1024×768 / phone 390×844 layout. Fixed a discovered mobile header scroll/clipping issue and verified panel scroll 0 and close target 44×44 px inside the viewport. A real NWI query succeeded in the UI and changed conditional acreage; an independent generic Texas query returned 30 wetland features. FEMA and NHD probes timed out and were not represented as verified absences.

No physical iPhone/iPad, authenticated production cloud save, or system print dialog was exercised in this local QA. Existing project persistence and print APIs are reused. No unrelated layer/tool/provider was removed. This implementation is local until separately published.

Deferred explicitly: footprint placement/rotations, terrain-wide slope grids, grading/cut-fill, practical-width/access verification and infrastructure proximity metrics. Existing line-profile elevation samples are not a defensible site DEM; terrain remains Not evaluated. No feasibility score, legal setback, utility capacity, tap/interconnection right, safety clearance or development approval is inferred.

Required result note: “Preliminary screening based on selected rules and available data. Survey, title, environmental, and engineering review may change these results.”

## Whole-layer study boundaries and reports (0.9.199)
Choose “all polygon features” under the existing polygon selector to screen a combined layer. Actual Polygon/MultiPolygon features are unioned in the same local metric projection used by the calculation engine; overlaps count once and holes/disconnected areas remain. Source geometry is unchanged. The existing complexity and supported extent limits still apply. Remote layers use their currently loaded feature snapshot, not an unbounded service download. Changes to saved local layer geometry invalidate the result; feature reordering does not.

“Add to Print Map” saves the current analysis and selects its summary panel. Print Map → Analysis reports supports one Buildable Area report plus one elevation profile on the same composition; the map is shortened to reserve a report row. Standard Print, Quick PDF and saved map copies include the selected panels. Standalone report PDF/SVG exports supplement existing full geometry and summary/rule GeoJSON exports. The standalone report is a concise summary; GeoJSON retains full rule/source metadata. Save the project to sync these snapshots.

## Automatic screening and terrain (algorithm 1.1.0)

Inventory: KEEP all existing layers, manual/imported constraints, polygon/whole-layer/rectangle selection, property clipping, setbacks, area accounting, component inspection, persistence, printing and exports. ENHANCE the existing panel/worker/source loader; add a bounded numeric DEM endpoint and modular policy/terrain helpers. No existing capability or public catalog entry was removed. No new provider login, dependency or database schema is required.

Workflow: select the study boundary, click **Optimize & Run**, then edit **Parameters, grade & sources** and individual constraint rules and use **Run / rerun screening**. Optimize fills missing catalog presets and preserves existing treatments, buffers, enabled states and overrides. First optimization deducts conditional areas; subsequent runs preserve that choice. Selecting a profile does not silently overwrite edited parameters; the reset-terrain-defaults action is explicit.

Automatic policy `LandDraft screening 1.0`:
- Exclude mapped NWI wetlands, NHD water bodies/areas, FEMA 1% annual-chance floodplain and regulatory floodways by conservative screening policy. No legal prohibition or jurisdiction is inferred.
- Hold the 0.2% floodplain conditional; use a provisional 50 ft stream-centerline buffer. EPA's 50 ft CGP sediment-control alternative is context, not a universal development setback or a surveyed bank boundary.
- Texas-region study bounding boxes request existing Texas transmission/pipeline/road/rail catalog services; provisional conditional half-widths are 50/50/30/50 ft. Nationwide turbine points use a provisional 300 ft radius. These are editable LandDraft planning allowances, not recorded ROW/easements, actual facility footprints, legal setbacks, safety clearances or access/capacity findings. Texas selection is a broad regional bounding-box heuristic; service scope/absence remain uncertain outside actual mapped coverage.
- Property setbacks and study margins retain the user's explicit settings; no local ordinance is invented.
- Existing categories without connected sources remain Not evaluated. This is not an exhaustive environmental/title/geotechnical investigation.

Source basis links are retained on each auto rule and displayed in the panel: USFWS Wetlands Mapper limitations; EPA Construction General Permit buffer FAQ; FEMA Floodway Analysis and Mapping (2019); NRCS NH Envirothon Soil Guide (2020), which uses 8–15% and >15% site limitations for a homesite example; USGS About 3DEP Products & Services. General terrain defaults are conditional ≥8% grade, exclusion ≥15%, conditional local elevation range >3 m within a requested 50 m window. Data Center defaults are 5%/10% and >2 m/50 m, explicitly LandDraft assumptions rather than a validated data-center design standard. A 10% grade is rise/run ×100, not 10 degrees. No universal threshold establishes development feasibility.

Terrain endpoint POST `/api/analysis/buildable-terrain` requests a numeric, unrendered, single-band F32 USGS 3DEP ImageServer grid with nearest-neighbour resampling, a local UTM CRS and an explicit validity mask. It uses the documented ArcGIS BIP pixel stream (little-endian floats, MSB-first bitmask), not colour-image inference or sparse profile interpolation. The server accepts only bounded UTM extents/dimensions, never an arbitrary URL. Output cells are requested at 10 m by default and increase in 5 m steps, at most 60 m, to fit 256×256 including a neighbourhood halo. Unsupported/oversized grids fail explicitly. Actual spacing, source resolution unknown, DEM datum uncertainty, retrieval time and publisher metadata where available are retained. Publisher metadata is not a local acquisition/survey date. Grid spacing is not accuracy; resampling does not create finer source detail.

The worker derives percent grade as the maximum of Horn 3×3 gradient magnitude and absolute eight-neighbour drop grade, and computes min/max local elevation range. The window radius is rounded outward to complete cells (e.g. requested 50 m becomes a 60 m centre-to-centre window at 10 m spacing); this is reported. All neighbourhood samples are required. Missing samples/neighbours become conditional unknown terrain, never zero or flat. These are local terrain screens, not pad fit, grading feasibility, cut/fill, drainage design or a complete cliff survey. Features smaller than the sampling/source resolution can be missed. Grid summary extrema/counts cover the bounding grid; constraint acreage is clipped to the actual study/property geometry.

Raster masks are polygonised along exact pixel edges using 4-connected components, preserving holes and disjoint areas. Only collinear edges are simplified. Zero-distance topology normalization handles point-touching digital rings and is accepted only if area agrees with the exact pixel count; invalid/non-reconciling terrain fails. Projected constraint polygons enter the existing union/difference acreage engine, so overlapping constraints are counted once. Geometry budgets/timeouts still apply. Terrain rule edits survive regeneration, and original input geometry remains unchanged.

Critical source failures/partial responses whose geographic gaps are unknown hold the full study conditional by default. This means **unresolved**, not physically unsuitable. Terrain's known gaps are held only in mapped unknown cells; a wholly failed terrain request holds the study conditional. Geometry-processing failures of required rules also hold the study conditional. Users can explicitly change the unresolved-data policy, disable a check, provide their own data, or change conditional treatment; source limitations remain visible. One bounded retry is made for transient source-query errors, with at most three source queries active. Cancellation/generation gates discard stale network/worker responses.

Snapshots and GeoJSON exports retain automation settings, rule basis/overrides, generated terrain geometries and terrain provenance. Saved analyses reopen without silently refreshing their data; rerun refreshes sources/DEM. Existing print summaries include terrain settings and full details remain in summary/geometry exports. The raw DEM grid is not stored in project snapshots; enough derived geometry and method/settings are retained to explain the saved result, but a later rerun may use newer source data.

Validation: synthetic metric planes, diagonal gradients, abrupt drops, local relief independent of slope, real zero versus NULL, unknown neighbourhoods, clipping/holes, coarsening/budgets, topology/area across 100 varied masks, defaults/overrides/idempotency, outage/recovery, geometry failure holds and API validation. Read-only live probes loaded a 103×122 10 m USGS grid near Amarillo; three values differed from the USGS EPQS point service by ~0.06–0.17 m (cross-service consistency, not an accuracy certification). Its ~249.96-acre test rectangle produced ~1.75 ac steep exclusion and ~3.47 ac conditional terrain. Wetlands and several infrastructure services responded; FEMA connections and some NHD queries failed/timed out during the probe. No unverified alternative source was silently substituted. Source availability remains an external limitation.

Manual QA for automatic screening used the actual panel, geometry worker and MapLibre with an isolated test store, synthetic public-layer responses (including a wetland polygon), and a real request to the new USGS endpoint. Verified Optimize adds 12 public-source rules plus 3 terrain rules, computes/draws candidate/excluded/conditional polygons, preserves the 249.96 ac source boundary, changes candidate area from ~234.73 to ~164.23 ac when thresholds tighten from 8/15% to 2/4%, marks a simulated wetland outage unresolved, recovers on rerun, and exports automation settings and terrain provenance. Checked phone 390×844 controls/header/scroll/export and restored the viewport. No authenticated production project was modified; cloud persistence and physical-device/system-print verification were not repeated. The preview uses the same emitted MapLibre worker setup as the actual app.

## Boundary chooser layer refresh fix
The boundary chooser now inventories `displayLayers`, including subproject overlays, instead of only primary-project layers. Every layer has a stable whole-layer option with loaded polygon count or a loading/empty/nonpolygon explanation; empty remote sources no longer disappear. Newest layers sort first and a name/feature search is available. Individual-feature previews are fairly distributed across layers (25 per layer, up to 800 total), while map-selected features are prioritized and whole-layer choices remain uncapped. Imported GeometryCollections use their actual polygon parts. Saved Buildable Area layers offer candidate features only, never the gross study or exclusions.

An explicitly selected remote source can load/refresh polygons in the current map view without changing map extent, map data or other project layers. Filters/selected fields are retained; requests enforce feature/coordinate budgets, pagination/count reconciliation, cancellation and project/unmount cleanup. Partial/truncated fetches are rejected as study boundaries. The panel retains the resulting snapshot while map viewport data changes; it is visibly described as a current-view snapshot rather than the entire service. Existing whole-layer snapshots still explicitly mean loaded polygon features, not all parcels nationwide. Whole-layer and mixed-geometry edit detection compares the same polygon geometry that was selected.

Regression coverage includes a new layer behind an earlier 1,000-feature layer, selected features outside preview limits, empty remote sources transitioning to loaded polygons, subproject inventory, nonpolygon status, mixed geometry, candidate-only saved analysis reuse, bounded/filter-preserving remote loads, partial results and cancellation. No map layers/providers are removed.

Manual chooser verification: actual BuildableAreaPanel and MapLibre browser fixture confirmed a new layer appears while the panel stays open, whole-layer selection reports gross acreage, subproject boundaries are listed, and a previously empty remote layer loads a bounded snapshot into the chooser. Public responses were mocked for this UI check; remote truncation, filters, cancellation and geometry behavior are covered by automated tests.
